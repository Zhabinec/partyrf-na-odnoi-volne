# На одной волне

## Проверить одному — режим с ботами

На стартовом экране нажмите **«Тест с ботами»**. В окне укажите имя и выберите количество ботов кнопками −/+, либо введите число. Можно выбрать от 2 до 9 ботов; окно сразу показывает общий состав компании. По умолчанию выбрано 5. Нажмите «Собрать компанию», затем начните партию из лобби.

Боты сами отвечают и голосуют, а вы проходите свои задания и листаете финал как хост. Обычное создание комнаты ботов не добавляет.

Для проверки без Render скачайте репозиторий через **Code → Download ZIP**, распакуйте и выполните `node server.mjs` из папки игры (нужен Node.js 22+). Пакеты устанавливать и собирать проект не требуется. Откройте адрес из терминала и выберите «Тест с ботами». После скачивания проекта и установки Node.js интернет для самой игры не нужен: музыка и эффекты локальные.

Тумблер режима — `TEST_BOTS`: `1` включает кнопку, окно настройки и API; `0` отключает все три. После изменения переменной перезапустите сервер. При отключении окно даже не включается в HTML страницы, а кнопка не оставляет пустого места.

## Играть компанией через интернет

**[Открыть игру](https://partyrf-na-odnoi-volne.onrender.com/)** · от 3 игроков · каждому нужен только браузер.

1. Один участник открывает ссылку, вводит имя и нажимает «Создать комнату».
2. В лобби он копирует приглашение и отправляет коллегам. Каждый открывает его на своём устройстве, вводит имя и входит в ту же комнату.
3. Когда собрались минимум трое, хост начинает партию. Ничего устанавливать или регистрировать участникам не нужно.
4. Для телевизора или трансляции хост открывает **«Меню → Общий экран»**. Игроки продолжают отвечать со своих устройств. При игре из разных мест используйте отдельный голосовой звонок: встроенного голосового чата нет.

Демо работает на бесплатном Render. После простоя первое открытие может занять около минуты. Дождитесь загрузки и создайте новую комнату. Все участники используют один адрес игры; комнаты между разными играми не общие.


## Проверка живой компанией

Один организатор скачивает этот репозиторий, устанавливает [Node.js 22+](https://nodejs.org/) и запускает из папки игры команду ниже. Зависимостей нет, устанавливать пакеты не требуется. Остальные участники открывают игру в браузере; каждый отвечает со своего устройства. Минимум три игрока.

1. Организатор выполняет `node server.mjs`. Терминал оставляет открытым.
2. Для устройств в одной Wi-Fi/локальной сети: узнайте IPv4 компьютера командой `ipconfig` и откройте `http://ЭТОТ-IP:4173` на всех устройствах. При первом запуске разрешите Node.js доступ в частной сети в брандмауэре Windows. Гостевая Wi-Fi-сеть может изолировать устройства.
3. Организатор создаёт обычную комнату и копирует ссылку из лобби. Остальные входят по ней со своими именами. Ссылка с `localhost` работает только на компьютере организатора — для телефонов нужен адрес из шага 2.
4. Хост начинает партию. Через «Меню → Общий экран» можно открыть отдельную вкладку для телевизора или трансляции: это зрительский экран без личного ответа и секретного слова. Ответы вводятся на устройствах игроков.
5. Для проверки повторного подключения обновите вкладку игрока. Для проверки передачи роли хоста выйдите из комнаты через меню — управление перейдёт другому участнику.

## Проверка из разных городов

Нужен один доступный через интернет Node.js-сервер. Каждый участник **не должен запускать свою копию сервера**: это создаст независимые комнаты. Сам репозиторий не является игровой ссылкой.

Бесплатный вариант — [Render Free](https://render.com/docs/free). В репозитории есть `render.yaml`:

1. Опубликуйте код в своём GitHub-репозитории и подключите его в Render через **New → Blueprint**. Альтернатива: **New → Web Service**, среда Node, тариф Free, сборка `node --version`, запуск `npm start`.
2. Render выдаст HTTPS-адрес вида `https://имя.onrender.com`. Отправьте его участникам. Создайте обычную комнату и поделитесь её ссылкой. Участникам не нужны Node.js, GitHub или аккаунт Render.
3. В Blueprint режим с выбранным количеством ботов включён через `TEST_BOTS=1`; отключается значением `0`. Реальные игроки подключаются к одному серверу. Для общего экрана по-прежнему доступен пункт меню у хоста.

На Free сервер засыпает после 15 минут без запросов; первый запуск после простоя может занять около минуты. Комнаты хранятся в памяти: сон, перезапуск или новая публикация сбрасывают партии. Используйте один экземпляр сервиса. Создавайте комнату после пробуждения сервера; сохранность старой комнаты не гарантируется. Это вариант для демонстрации, а не постоянного хранения партий.

Без аккаунта можно использовать [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/): установите `cloudflared`, запустите игру и во втором терминале выполните `cloudflared tunnel --url http://127.0.0.1:4173`. Откройте выданный HTTPS-адрес, создайте комнату уже по нему и отправьте ссылку участникам. Адрес работает, пока включены компьютер, сервер и туннель, и меняется при перезапуске туннеля.

## Быстрый запуск на компьютере


Сетевая браузерная игра на 3–10 человек. Каждый предлагает тему, получает одну из тем в случайной раздаче и тайно оценивает её от −100% до +100%. Затем компания по очереди угадывает оценку каждого игрока. Ближайшие догадки получают по очку.

## Запуск

Нужен Node.js 22 или новее. Пакеты устанавливать не нужно.

```powershell
node server.mjs
```

На компьютере с сервером откройте http://localhost:4173. Чтобы игроки подключились с телефонов по одной сети Wi-Fi, откройте игру по локальному IPv4-адресу компьютера с сервером и создайте комнату с этого адреса. Тогда ссылка из лобби будет доступна другим устройствам. На компьютере должен быть разрешён входящий трафик на порт 4173.

Для игры через интернет разместите папку на хостинге с Node.js и HTTPS. Одна команда запуска — `node server.mjs`. Порт задаётся переменной `PORT`, адрес привязки — `BIND_ADDRESS`. Хост создаёт комнату из браузера на этом же сервере.

## Партия

- Хост отправляет ссылку или шестизначный код и начинает игру после подключения минимум трёх человек.
- На тему даётся 55 секунд, на тайную оценку — 40, на каждое угадывание — 30. Фаза заканчивается раньше, если ответили все.
- После угадывания игра запечатывает ответы и автоматически переходит к следующему игроку. При равной минимальной ошибке очко получает каждый из ближайших. При равенстве итоговых очков победа общая.
- В финале все смотрят одни и те же карточки. На карточке сразу видны оценка, реакция и догадки. Иногда после нажатия «Следующая карточка» появляется отдельный экран «А почему?». Хост листает дальше, когда компания готова. После последней карточки идут отдельные экраны с победителем, моментом партии и послесловием с таблицей и подробностями.
- Перезагрузка вкладки восстанавливает сессию комнаты. Комнаты хранятся в памяти одного процесса, поэтому перезапуск сервера завершает партии.

## Модули

Кнопка **«Тест с ботами»** создаёт комнату с выбранным количеством ботов прямо в игре. Имя можно оставить пустым. После «Начать игру» боты отправляют темы, оценки и догадки, а ты играешь и листаешь финал как хост.

Чтобы скрыть кнопку и отключить создание тестовых комнат, перезапусти сервер с флагом:

```powershell
$env:TEST_BOTS='0'
node server.mjs
```

Чтобы вернуть режим, установи `TEST_BOTS=1` и перезапусти сервер. Логика ботов находится в `src/test-bots.mjs`.

После входа в комнату у каждого игрока звучит [Surf Shimmy](https://incompetech.com/music/royalty-free/index.html?isrc=USUAN1700018) Кевина Маклауда (Incompetech), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Кнопка «Звук» открывает отдельные ползунки музыки и эффектов. Настройки сохраняются в браузере.

Перебивки, отсчёт и финал используют [бесплатные эффекты Mixkit](https://mixkit.co/license/): [Water splash](https://assets.mixkit.co/active_storage/sfx/1311/1311-preview.mp3), [Water bubble](https://assets.mixkit.co/active_storage/sfx/1317/1317-preview.mp3), [Clock ticker single](https://assets.mixkit.co/active_storage/sfx/1061/1061-preview.mp3), [Tension and suspense drum roll](https://assets.mixkit.co/active_storage/sfx/577/577-preview.mp3) и [Audience light applause](https://assets.mixkit.co/active_storage/sfx/354/354-preview.mp3).

- `src/game.mjs` — правила, фазы, счёт и персональные снимки состояния. Модуль не зависит от браузера и HTTP.
- `server.mjs` — комнаты, сессии игроков, серверные таймеры и HTTP API. До раскрытия клиенту доступны только данные для его текущего действия.
- `src/main.js` — запросы к комнате и обработка действий.
- `src/ui.js`, `index.html`, `styles.css` — интерфейс на HTML, CSS и JavaScript.

## Проверки

`npm test` проверяет полную партию, скрытие секретов на общем экране, повторный запуск, независимые HTTP-сессии, восстановление подключения и передачу хоста. Тесты используют локальные временные серверы без внешних зависимостей.

## Надёжность прототипа

- Обновление вкладки сохраняет сессию. После 15 секунд без запросов игрок считается временно отключённым; хост переходит подключённому человеку, боты хостами не становятся. Возврат по прежней сессии не отбирает управление обратно. Если уже началась другая партия, вернувшийся ждёт её окончания.
- Явный выход и временный обрыв различаются: после выхода через меню прежняя сессия закрыта. Уже принятые ответы сохраняются для истории.
- При изменении состава комнаты в том же ходе незаконченная форма сохраняется вместе с текстом, курсором и шкалой. При новом ходе или принятом ответе форма заменяется.
- Создание комнат ограничено 30 запросами в минуту на весь экземпляр демо. При превышении API возвращает HTTP 429 и `Retry-After`. Вход по приглашению не расходует этот лимит. Это базовая защита демо, не полноценная защита от DDoS.
- GitHub Actions запускает `npm test` на Node.js 22 и 24 при push и pull request. Проверяются также обрывы связи, ограничитель комнат и точное начисление очков.

При обычном закрытии вкладки игра отправляет сигнал серверу: после примерно 5 секунд без нового запроса хост передаётся подключённому участнику. Перезагрузка за это время сохраняет роль. Если сигнал отправить невозможно, действует резервный тайм-аут 15 секунд. В лобби имя отключённого игрока можно использовать заново; это создаёт новую сессию и закрывает прежнюю. Во время активной партии новый вход по имени не восстанавливает чужую роль.

Выход через меню подтверждается сервером. Если связь оборвалась, запрос сохраняется в браузере и повторяется; перед следующим входом игра завершает этот выход.
